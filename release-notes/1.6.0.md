## 博客 1.6.0

### 站点更新

- 移除“在线更新”操作按钮、更新说明下的全部操作按钮和“查看 Release”入口，版本操作统一到右上角。
- 主按钮状态改为：
  - 无更新：`暂无更新`
  - 有更新：`下载安装`
  - 下载中：`下载 xx%`，按钮内部显示进度填充
  - 下载完成：`安装 vX`
- 下载改为后端持久化任务，创建后写入 `ota_download_tasks` 表；切换后台页面或刷新浏览器后按任务 ID 恢复进度。
- 下载进度包含总大小、已下载字节、百分比、当前步骤和失败原因。
- 下载完成后继续执行 Spring Boot 启动类、应用配置、文件完整性、SHA-256 和磁盘空间校验。
- 服务重启时会把未完成下载任务标记为失败，避免展示错误进度。

### 代理与缓存

- 右上角新增“清理缓存”，清空 GitHub Releases 列表缓存，下一次读取重新请求 GitHub API。
- 新增“代理前缀”弹窗，配置保存到数据库。
- 留空为直连；只输入域名会自动补全 `https://` 与末尾斜杠。
- 默认推荐代理前缀：`https://ghfast.top/`。
- 代理只用于 Release 资产下载，目标来源仍限定为 GitHub Release。

### 回档

- 历史版本移除“在 GitHub 查看”按钮。
- 每个历史版本新增“回档到此版本”。
- 点击后展示风险确认：旧版本可能不兼容现有数据、回档后新功能不可用、安装过程会重启站点。
- 下载完成后不会自动安装，需要再次点击右上角“安装 vX”并确认。
- 待安装区域对回档操作显示独立风险提示。

### 验证

- 后端 Maven `-DskipTests package` 成功，前端 Vite 生产构建成功。
- 真实 H2 实例验证下载任务从 12% 持续更新到 69%、87%，切换后台页面与刷新浏览器后进度保持。
- 验证代理前缀持久化、代理下载、清理 Release 缓存、历史版本回档风险弹窗和下载完成后的安装状态。
- 验证无更新、下载中、下载完成三种主按钮状态。

### 下载

- `blog.jar`：完整可执行包，Java 17+，`java -jar blog.jar`。
- `blog.jar.sha256`：SHA-256 校验文件。

### 升级说明

- 直接替换 `blog.jar` 后重启即可，Hibernate 会自动创建 `ota_download_tasks` 表。
- 原有文章、用户、通知、标签、AI 和存储配置保持不变。
- 首次升级后，下载进度恢复能力需要新版本 jar 生效。
