# 博客 1.16.0 · 后台减负与提醒中心

本次更新集中梳理后台管理：移除重复的主题体系，把评论审核收回评论管理，并把“通知设置”升级为真正的提醒中心。目标是少一点无效入口，多一点能用的开关。

## 提醒中心

- 通知设置新增“提醒偏好”：新评论、喜欢、收藏、版本更新、新用户五类互动通知可分别关闭或开启。
- 新增“仅提醒待审核评论”：开启评论先审后发后，可只接收待审核评论提醒，直接展示的评论不再打扰。
- 新增“发送测试提醒”，用于快速确认后台互动通知链路是否正常。
- 首页通知列表支持按标题/内容搜索，并可按通知、更新、系统类型筛选和重置。
- 提醒偏好卡片提供“查看互动通知”入口，直接回到仪表盘的互动通知区域。
- 新用户注册会写入互动通知；开启注册审批时标题为“新用户待审核”，否则为“新用户注册”。
- 通知类型补齐“用户”“测试”的图标与配色，仪表盘可区分来源。

## 评论管理

- “评论先审后发”从站点信息迁移到评论管理顶部，开关即时保存，已有评论状态不受影响。
- 新增评论批量操作：当前页全选、批量通过、批量隐藏、取消选择；一次最多处理 200 条。
- 待审核评论的互动通知改为跳转 `/admin/comments?tab=pending`，不再跳到一个看不到该评论的前台页面。
- 前台评论提交提示会在开启审核时显示“审核通过后展示”；评论与回复补上锚点，已展示评论的互动通知可精确定位到对应楼层。

## 主题管理

- 移除“主题管理”页面、后端主题接口、侧栏入口、路由与仪表盘快捷入口。
- 移除 `themePreset` 预设配置及全部 `data-preset` 样式，站点只保留全局浅色/深色/跟随系统三种显示偏好。
- 角色权限目录同步移除已废弃的主题权限项。

## 修复与优化

- 修正互动通知链接：由错误的 `/posts/{id}` 统一改为前台实际路由 `/post/{id}`。
- 修复提醒偏好开关只有输入框状态、没有视觉开启态的问题。
- 修复评论审核卡片横向布局被挤压、正文逐字换行的问题。
- 通知类型筛选、空结果提示与测试提醒文案做了统一。

## 升级说明

- 版本号升级至 `1.16.0`，数据库结构无需迁移。
- 旧数据库里即使残留 `themePreset` 配置行也不会再被读取，可忽略。
- 关闭“提醒偏好”只影响后台互动通知，不影响站内公告或邮件服务。
- 评论批量审核为整批事务：任一条处理失败会整批回滚，不会出现部分成功。
