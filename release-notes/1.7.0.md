## 站点更新

- 版本号改为读取当前运行的 jar：优先 `META-INF/MANIFEST.MF` 的 `Implementation-Version`，其次 `build-info.properties`、`pom.properties`。手动替换 jar 并重启后，旧 `APP_VERSION` 不会再让页面显示旧版本。
- 站点更新右上角新增「本地升级」：弹窗选择 `.jar`，显示文件大小、上传进度与校验结果；校验通过后进入待安装区，不自动替换程序。
- 「清除缓存」现在清理已下载的待安装包、staging 残留、下载任务记录与 Release 列表缓存；本地上传的待安装包保留，下载任务进行中会拒绝清理。
- 更新成功启动后自动清理历史备份 `updates/backups/`、staging、`updater.jar` 与下载任务历史；GitHub 历史 Release 保留用于回档。
- 待安装区显示来源：本地上传 / GitHub 在线下载 / 回档下载。

## 存储管理

- 本地存储根目录改为 jar 同级 `local-storage/`，自动创建 `images/`、`audio/`、`video/`、`documents/`、`archives/`、`other/` 分类文件夹。
- 旧 `uploads/` 文件首次启动自动复制迁移；旧 `/uploads/<文件名>` 保持可访问，新文件地址为 `/uploads/<分类>/<文件名>`。
- 新增 `stored_files` 元数据表，列表展示上传人、文件名、分类、文件类型、大小、上传 / 修改时间与访问地址。
- 支持按文件名、上传人、文件类型 / 分类关键字搜索，以及分类和上传人筛选。
- 新增 WebDAV 与 OpenList 存储：WebDAV 使用 Basic Auth；OpenList 只填站点根地址时自动补 `/dav`，默认公开直链为 `/d/<对象路径>`。
- 线上存储模式不显示本地文件列表、本地目录统计、分类文件夹与本地路径；本地文件接口同时拒绝线上模式访问。

## 升级说明

- 默认本地存储位置从 `./uploads` 变为 jar 同级 `local-storage`。首次启动会创建分类目录并复制旧 `uploads` 文件，不删除原目录。
- 如果显式设置 `UPLOAD_DIR`，仍以该目录为准，不做自动迁移。
- Docker 部署需要使用新的 `docker-compose.yml` 挂载 `./local-storage:/app/local-storage`，并保留 `./uploads:/app/uploads` 以便首次迁移。
- 更新成功后 `updates/backups/` 会被清空；需要保留历史本地包时请在更新前自行备份。GitHub Release 历史版本仍可在页面回档下载。
