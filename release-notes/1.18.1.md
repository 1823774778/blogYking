# 博客 1.18.1 · 音源兼容修复与热歌榜播放器

这次更新处理生产环境导入音源时的 GraalJS 初始化失败，并把前台音乐浮窗改成可拖动、默认展示各平台热歌榜的播放器。

## 音源导入修复

- 将 `org.graalvm.polyglot:polyglot` 与 `js-community` 从 `23.1.2` 升级到 `25.0.5.1`，解决旧版 GraalJS 与较新 JDK 的兼容问题。
- 移除 `engine.WarnInterpreterOnly` 选项，避免不同 GraalJS 版本对引擎选项的支持差异导致初始化异常。
- 音源初始化异常捕获从 `RuntimeException` 扩大为 `Exception | LinkageError`，并递归提取最底层原因。
- 导入失败时不再只显示 `NoClassDefFoundError: Could not initialize class org.graalvm.polyglot.Engine$ImplHolder`，而是尽量展示真正导致 `ExceptionInInitializerError` 的根因。
- 升级后 fat jar 从约 182MB 降至约 158MB。

## 热歌榜接口

- 新增公开接口：`GET /api/music/charts?platform=wy&limit=20`。
- 网易云：官方「热歌榜」。
- QQ 音乐：官方「巅峰榜·热歌」。
- 酷狗音乐：官方「TOP500」。
- 酷我音乐、咪咕音乐：因缺少稳定的公开榜单 JSON 接口，使用平台热门搜索兜底，响应中带 `fallback: true`，界面标注“平台热门推荐”。
- 榜单按平台分别缓存 10 分钟；手动刷新会重新获取。
- 返回字段包含 `platform`、`platformLabel`、`chartTitle`、`fallback`、`updatedAt`、`tracks`，曲目字段同时兼容播放器队列所需的 `id/source/title/artist/album/cover/duration/fee/vip`。

## 前台音乐浮窗

- 展开后默认进入「热歌榜」，顶部可在网易云、QQ、酷狗、酷我、咪咕之间切换。
- 榜单展示排名、封面、歌名、歌手、专辑、时长和 VIP 标识；支持单曲点播与「播放全部」加入队列。
- 播放器面板可按住标题栏拖动到视口内任意位置，位置写入本地存储；窗口尺寸变化时自动限制在可视范围内。
- 悬浮球也可拖动，和面板位置分别记忆；拖动后不会误触发打开/收起。
- 点击榜单歌曲或「播放全部」时，若 320k/FLAC 音质解析不到地址，会自动回落到 128k 再试一次，避免免费曲目因默认高音质直接失败。
- 移动端仍使用底部全宽面板，不启用桌面拖拽，避免与页面滚动冲突。
- 切换平台或重新加载榜单时自动回到榜单顶部，旧请求不会覆盖当前平台的数据或错误提示。

## 升级说明

- 版本号升级至 `1.18.1`，数据库结构无需迁移。
- 本次修改不改变旧接口 `/api/music/playlist`、`/api/music/search`、`/api/music/url` 的调用方式。
- VIP、付费或版权受限曲目仍遵守平台限制，点击后可能提示“暂时无法播放”，不会绕过版权校验。
- 若生产环境升级后仍出现音源初始化失败，请提供 `java -version` 和导入失败时完整异常链，便于继续定位 JDK 与 GraalJS 的具体兼容问题。

- 使用 JDK `17.0.13` 启动 `1.18.1` 测试站，后台音源预览六音 `1.2.1` 初始化成功，平台 `kw/kg/tx/wy/mg`，测试曲目播放地址 PASS。
- 五平台榜单接口实测均返回 200：网易云、QQ、酷狗为官方榜单；酷我、咪咕为热门搜索兜底。
- 在 1440×900 浏览器视口实测：展开默认网易云热歌榜，五个平台标签完整可见；切换 QQ 热歌榜后列表正常；标题栏拖动从 `(1026,120)` 移到 `(249,202)`，刷新后位置恢复；悬浮球从右下角拖到页面中部后不会误触打开面板。
- QQ 免费曲《慌啥子嘛（赵本山版）》在默认 320k 解析为空时自动回落 128k，播放器成功取得音频地址并开始播放。
- 前端 `npm run build` 成功；后端 `mvn -DskipTests package` 成功；`blog.jar` 约 158MB。
